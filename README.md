# ABR | CIVIL — Картограмма земляных масс

Построение и оформление плана земляных масс по ГОСТ 21.508-2020 для Autodesk Civil 3D 2015-2024 (сборка net48) и 2025 и новее (сборка net8).
Живой гейт пройден на 2024. На 2021 версия 1.0.0 падала с MissingMethodException
(`TinSurfaceTriangle.IsVisible` - член API только с 2024); исправлено в 1.0.1,
живой гейт 1.0.1 на 2021 ещё не пройден.

Расчёт объёмов по двум поверхностям тремя методами: метод квадратов, по площади и средней отметке,
точный по поверхностям.

Установка — через Библиотеку модулей ABR | CIVIL.

## Живой гейт этапа 1 (2026-08-04)

Проверено на реальном проекте пользователя, Civil 3D 2024, две TIN-поверхности, шаг сетки 20 м,
без указания наружного контура (область = пересечение поверхностей целиком).

Точный метод по поверхностям, 121 фигура, 112 узлов:

| | Наш расчёт | Эталон Civil 3D (TinVolumeSurface) | Расхождение |
|---|---|---|---|
| Насыпь | 2534.0 м³ | 2551.9 м³ | -0.70 % |
| Выемка | 86.2 м³ | 87.4 м³ | -1.30 % |

Времена: чтение поверхностей 23 мс, расчёт 167 мс, всего с отрисовкой 217 мс.

Метод квадратов (ГОСТ) на том же чертеже отошёл от эталона заметно сильнее (насыпь -14.71 %,
выемка -58.74 %) - ожидаемое свойство метода: он усредняет рабочую отметку по 4 вершинам
ячейки сетки и не видит выемку, если она локальным пятном сидит внутри клетки, а все 4 угла
клетки - насыпь. Точный метод считает по пересечению треугольников обеих поверхностей и такой
слепой зоны не имеет.

`CARTOGRAMUPDATE` пересчитал сохранённую картограмму с теми же числами. `CARTOGRAMERASE` удалил
все объекты и записи; повторный `CARTOGRAMUPDATE` корректно сообщил об отсутствии картограмм.
`Ctrl+Z` сразу после построения откатил картограмму одной операцией.
